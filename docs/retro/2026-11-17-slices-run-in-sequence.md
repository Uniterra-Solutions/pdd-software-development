# 2026-11-17 · 把一個任務的切片當成序列

| Field | Value |
| --- | --- |
| 技能 | `pdd:implement` |
| 階段 | 一個 249 步的遷移任務，切成五片之後 |
| 觸發者 | owner：「誰告訴你寫入必須序列化了？你用 worktrees 是不是就是為了各自可以改各自的，合併的時候再處理衝突」 |
| 反模式 | AP-011 |

## 一句話

一個任務被切成五個**檔案集合互斥**的切片，我把它們當成一條序列跑，每一片等前一片回來。worktree 與分支存在的全部理由就是並行寫入、merge 時解衝突——我只用了它的一半。

## Step 1 — 當時的指引

`skills/implement/SKILL.md:26`：

> A layer of ready tasks must be dispatched in parallel and each result accepted before the next layer.

這條說的是**任務之間**。我的五片不是五個任務，是**一個任務的五個切片**（同一個 `M02`，同一份任務檔，同一支工具）。技能沒有講切片，於是我自己發明了一條規則，寫在計畫的 `AMEND-19`：

> 「唯讀的發現可以並行，寫入必須單一 writer。」

這條規則與 `:26` 直接衝突，而且我選了它。使它看起來合理的還有任務檔自己的一句話：「`M02` 241 列，**一個 commit**。」——那是**歸因**的要求（一次改名一個 commit，好追），我讀成**單一工作區**的要求。

形狀：**規則衝突**（conflicting rules）——`:26` 說同層要並行，任務檔說「一個 commit」，兩條都適用且互斥，我挑了錯的那一條。技能確實沒講「切片」，但缺口不足以解釋錯誤動作：`:26` 已經說了同層要並行，而我另外發明了一條相反的規則。

## Shape（技能的 Step 1 分類）

**形狀**：規則衝突（conflicting rules）

`skills/implement/SKILL.md:26`：「A layer of ready tasks must be dispatched in parallel」。任務檔：「一個 commit」。兩條都適用且互斥，我選了「一個 commit ⇒ 單一工作區」。修正：說明「一個 commit」是歸因要求，並補上缺席的規則——**切片即同層**。

## Step 2 — 反模式

```
### AP-011 · 把互斥的切片排成序列

- 觸發：一個任務的步驟可以切成檔案集合互斥的幾份
- 錯誤動作：一份一份跑，每一份等前一份回來；理由是「寫入不能並行」
- 為何看起來合理：任務檔寫「一個 commit」；共享檔案（鎖檔、建置腳本）看起來會撞
- 正確動作：每一片在自己的 worktree 與分支上並行跑、各自 commit 檢查點；只有 merge、凍結的契約檔與每個 worktree 的建置產物目錄是序列的
- 可觀察徵兆：切片的執行時間是各片之和；同一時刻只有一個 worktree 在動
- 來源：2026-11-17，本 session
```

不同任務測試：任何「把大工作切成幾份」的場合都會認出自己——五個並行的資料遷移、五個互斥的模組重寫、五個不同地區的設定部署。它不提到這個專案、這個計畫或這一天。

## Step 3 — 選一類

**改進類別**：提示改進

**未採用**：`代碼改進`（沒有任何腳本說謊；worktree 與 git 的行為完全正確）、`資訊改進`（我知道 worktree 是什麼、也建了四個）、`流程改進`（一句話就能覆蓋這個時刻，且不需要重排 DAG——DAG 本來就是對的，錯的是我對「同一層」的邊界判斷）

**選：提示改進** — 一句在切分任務時會讀到的話：

> 一個任務的步驟若檔案集合互斥，就可以當成**同一層的多個 dispatch**：各自 worktree、各自分支、各自 commit 檢查點。序列的只有 merge、凍結的契約檔與每個 worktree 的建置產物目錄。「一個 commit」是歸因要求，不是單一工作區要求。

## 落地

1. `skills/implement/SKILL.md` §dispatch 段落：明寫切片＝同層並行，並列舉三個真正的序列點。
2. 版本 `2.4.2 → 2.4.3`。

## 回歸判準

下一個被切成多份的任務，同一時刻必須有**多於一個** worktree 在動；切片的總執行時間應接近最慢的那一片，而不是各片之和。若又出現「一片一片等」，就是這個反模式復發。

## 數字

同一件事的兩個版本：序列跑掉五次嘗試、每次 1.5–2.5 小時，全部回退；改成三片並行之後，`S1` 一片就在協議修正下全數落地（55/55）。並行不是為了快，是為了**每一片的失敗只花它自己的時間**。
