## 一句話

一次模組搬移讓一個測試掛載宣告消失，**十個測試案例靜默蒸發**，而測試清單檢查器以 exit 0 回報成功。

## Shape（技能的 Step 1 分類）

**形狀**：沉默缺口（silent gap）

缺口：`skills/report/references/gate-discipline.md` —— 五條 Rule 講的都是「閘門要紅得對」，**沒有一條講基線腳本的預設模式**（比較 vs 寫入）。驗收文件只說「跑這支腳本」，於是它的輸出模式（只寫檔）被當成驗證。

## Step 2 — 反模式

```
### AP-007 · 只寫不比的檢查器

- 觸發：一支腳本同時有「寫出基線」與「與基線比對」兩種用途
- 錯誤動作：驗收時呼叫它的寫出模式，看到 exit 0 就當成通過
- 為何看起來合理：寫出成功是明確的成功；比對成功還要先有一份參考檔
- 正確動作：驗收只呼叫比較模式；寫入需要顯式旗標。比較鍵是語意鍵，不是位元組
- 可觀察徵兆：驗收指令把輸出指向一個新路徑，然後只看 exit code
- 來源：一次多步遷移的切片
```

## Step 3 — 類別

**改進類別**：代碼改進

**未採用**：`提示改進`（腳本無人值守）、`資訊改進`（我知道它有兩種模式）、`流程改進`（單一腳本的預設值）

## 落地

比較鍵改為三個語意鍵（名稱多重集、經改名正規化的逐單位集合、附檔摘要多重集）；三個控制：同一份清單 0、刪十筆指名十筆、只改單位名 0。第三個控制是關鍵：**改名不可以看起來像內容遺失**。

## 回歸判準

任何讓一個測試掛載消失的變更必須 exit 1 並列出遺失名稱；任何只改路徑或單位名的變更必須 exit 0。**寫檔不是驗證。**
